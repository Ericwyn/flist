# 媒体预览前后切换方案概述

## 背景

flist 已支持图片、视频、音频、PDF 和文本的在线预览，但当前每次只能从文件列表打开一个文件。用户连续查看同一目录中的多张图片或多个音视频文件时，需要反复关闭模态框、回到列表定位、再双击下一个文件，操作路径较长。

本次在现有 `PreviewModal` 中增加上一项 / 下一项媒体切换，让用户不离开预览即可按当前列表顺序连续浏览图片、音频和视频。该能力只涉及浏览器当前已经持有的文件列表，因此采用纯前端方案，不增加后端接口。

## 当前现状

### 目录预览主链路

```text
用户选择 sort / order
  -> fsStore.navigate / refresh
  -> GET /api/fs/list?sort=...&order=...
  -> res.items 写入 fsStore.entries
  -> FileBrowser 按 entries 顺序渲染
  -> 双击文件调用 openPreview(entry, fullPath)
  -> PreviewModal 根据 kindOf(entry) 渲染对应预览器
  -> /api/fs/download 流式返回媒体内容
```

关键位置：

| 模块 | 当前实现 |
| --- | --- |
| 排序状态与目录列表 | `frontend/src/fsStore.ts` 的 `sort`、`order`、`entries`、`navigate()` |
| 排序控件和打开入口 | `frontend/src/components/FileBrowser.tsx` 的排序工具栏、`openEntry()` |
| 搜索结果打开入口 | `frontend/src/components/FileBrowser.tsx` 的 `openHit()` |
| 当前预览状态 | `frontend/src/fsStore.ts` 的 `previewEntry`、`previewPath`、`openPreview()` |
| 文件类型识别 | `frontend/src/lib/path.ts` 的 `kindOf()` |
| 模态框和媒体播放器 | `frontend/src/components/PreviewModal.tsx` |

### 已有排序语义

1. 普通目录由后端依据用户选择的 `name / size / mtime` 和 `asc / desc` 排好，前端直接使用 `res.items`。
2. 网格视图和列表视图都按同一个 `entries` 数组渲染，因此两种视图顺序一致。
3. 搜索态会禁用目录排序控件，`SearchResultsView` 按 `searchResults` 的返回顺序展示。

### 当前不足

1. `PreviewModal` 只知道当前文件，没有上一项 / 下一项候选集合。
2. 图片、视频和音频预览均没有侧边切换入口。
3. 切换时如果重新按文件名排序，会破坏用户已选择的大小或修改时间排序。
4. 音视频控件会消费部分方向键，新增快捷键时需要避免干扰其原生快进、音量等行为。

## 目标

1. 图片、视频和音频的模态预览两侧展示向左 / 向右 icon button。
2. 将图片、视频、音频组成同一个媒体队列，在三种类型之间连续切换。
3. 普通目录严格保留当前 `entries` 的相对顺序，只过滤非媒体项，不二次排序。
4. 搜索态沿用当前 `searchResults` 的展示顺序。
5. 首项的上一项按钮、末项的下一项按钮保持可见但禁用，不循环跳转。
6. 支持键盘 `←` / `→` 切换，同时不抢占输入控件、CodeMirror 和音视频控件的方向键。
7. 视觉严格复用现有 Lucide 图标、slate 配色、圆角、阴影、暗色模式和 focus ring，不引入新的设计体系。
8. 不修改后端 API、数据库、权限模型或媒体下载链路。

## 非目标

1. 本期不为文本、未知类型或 PDF 增加前后切换按钮。
2. 本期不支持首尾循环、随机播放或自动连播下一个媒体。
3. 本期不新增缩略图带、媒体计数器等可见布局；当前位置仅通过无障碍 live region 提供。
4. 本期不新增触摸滑动手势、媒体预加载或播放进度跨文件保留。
5. 本期不请求超出当前已加载目录 / 搜索结果的新分页数据。
6. 本期不重构通用 `Modal`，切换控件仅属于 `PreviewModal`。
7. 本期不调整图片、音频卡片、视频播放器和下载按钮的既有视觉设计。

## 已采用的决策

1. **队列混合三类媒体**：图片、视频、音频统一按文件列表顺序切换，而不是只在同扩展名或同媒体类型内切换。
2. **只过滤、不重排**：目录结果已经代表用户当前排序选择；前端再次排序既重复又可能产生前后端语义差异。
3. **首尾不循环**：禁用到达边界的按钮，使“上一项 / 下一项”与可见列表方向一致且可预测。
4. **队列由现有状态派生**：不扩展 `fsStore` 的持久状态，也不在打开预览时复制快照；排序结果更新后预览队列同步更新。
5. **搜索使用展示顺序**：搜索页没有独立排序控件，因此以用户当下看到的顺序作为切换顺序。
6. **只在至少两个媒体时显示**：单个媒体没有可切换目标，不展示无效控件；多个媒体时两侧按钮始终存在，边界侧禁用。

## 核心设计

### 媒体队列来源

| 当前页面状态 | 队列来源 | 路径生成 | 顺序 |
| --- | --- | --- | --- |
| 普通目录 | `fsStore.entries` | `joinPath(currentPath, entry.name)` | 后端按当前 `sort / order` 返回的顺序 |
| 搜索结果 | `fsStore.searchResults` | 直接使用 `hit.path` | `SearchResultsView` 的展示顺序 |

队列过滤规则：

1. 只保留 `kindOf()` 为 `image`、`video`、`audio` 的普通文件。
2. 普通目录跳过 `unreachable` 条目，与 `FileBrowser.openEntry()` 的不可打开规则一致。
3. 文件夹、文本、PDF 和未知类型不进入队列，但不会改变媒体之间的相对顺序。

例如名称升序列表为：

```text
00-readme.txt
01-cover.png
02-theme.wav
03-trailer.mp4
04-poster.webp
```

对应媒体队列为：

```text
01-cover.png -> 02-theme.wav -> 03-trailer.mp4 -> 04-poster.webp
```

切为名称降序后，后端返回顺序反转，媒体队列自然变为：

```text
04-poster.webp -> 03-trailer.mp4 -> 02-theme.wav -> 01-cover.png
```

### 切换流程

```text
PreviewModal 读取当前页面列表
  -> 构建媒体队列（只过滤）
  -> 按 previewPath 找到 currentIndex
  -> 计算 previous / next
  -> 点击按钮或按方向键
  -> openPreview(target.entry, target.path)
  -> 标题、下载 URL、图片 / 播放器同步切换
```

媒体元素使用 `key={previewPath}`，确保从一个音频 / 视频切换到另一个时重新挂载播放器，避免旧媒体播放状态或资源残留。

### 按钮与键盘交互

1. 按钮使用 `ChevronLeft` / `ChevronRight`，尺寸、颜色和交互状态沿用现有 Tailwind utility。
2. 按钮位于媒体内容区左右边缘、垂直居中，不改通用模态框 header/footer。
3. `aria-label` 和 `title` 包含方向及目标文件名；边界态说明已经到达第一个 / 最后一个媒体。
4. `aria-live` 宣告“第 N 个媒体，共 M 个”，不增加可见 UI。
5. 无修饰键的 `ArrowLeft` / `ArrowRight` 触发切换。
6. 事件目标位于 `input`、`textarea`、`select`、`audio`、`video`、可编辑元素或 CodeMirror 时不接管按键。

### 方案取舍

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 前端基于 `entries` 派生队列 | 无新 API；天然匹配可见排序；改动集中 | 只能覆盖当前已加载结果 | 采用 |
| 后端提供 previous / next API | 可跨分页、可服务其他客户端 | 需传排序与过滤上下文，增加协议和请求延迟 | 本期不采用 |
| 打开预览时把完整队列写入 store | 切换期间顺序固定 | 增加冗余状态和失效同步问题 | 不采用 |
| 每种媒体独立队列 | 同类型浏览语义单一 | 音视频夹在图片间时与文件列表顺序不一致 | 不采用 |
| 首尾循环 | 可连续浏览 | 边界方向不明显，容易误以为存在更多文件 | 不采用 |

## 数据结构与协议

不新增或修改 HTTP API、后端 model、数据库字段、配置项或鉴权逻辑。

前端新增仅在浏览器内使用的结构：

```ts
interface MediaPreviewItem {
  entry: FileEntry;
  path: string;
}

interface MediaNavigation {
  currentIndex: number;
  total: number;
  previous: MediaPreviewItem | null;
  next: MediaPreviewItem | null;
}
```

## 兼容与降级

| 场景 | 行为 |
| --- | --- |
| 当前只有一个媒体 | 不展示切换按钮，现有预览不变 |
| 当前文件不在派生队列中 | 不展示切换按钮，不影响文本 / PDF 预览 |
| 已到第一个 / 最后一个媒体 | 对应按钮禁用，不循环 |
| 列表中包含目录、文本、PDF | 过滤这些条目，保留媒体相对顺序 |
| 条目不可达 | 普通目录队列跳过，避免切换到无法打开的文件 |
| 浏览器不支持某媒体编码 | 沿用现有原生播放器失败表现；切换和下载入口仍可用 |
| 搜索态 | 使用搜索结果展示顺序，不套用已禁用的目录排序控件 |
| 回滚到旧前端 | 后端无协议或数据变化，原单文件预览继续可用 |

## 可观测性

该功能不新增服务端请求或后台任务，因此不增加日志、指标和告警。

验证信号包括：

1. DOM 中按钮的可见 / 禁用状态和包含目标文件名的 `aria-label`。
2. 模态框标题、下载 URL 和媒体元素 `src` 随 `previewPath` 变化。
3. 现有 `/api/fs/download` 请求状态；视频仍可使用 Range 206。
4. 浏览器控制台不出现新增 warning / error。

## 测试计划

### 单元测试

1. 目录媒体队列保持输入顺序，跳过文件夹、文本和不可达条目。
2. 搜索媒体队列保持 `searchResults` 顺序和完整路径。
3. 图片、视频、音频可组成混合队列。
4. 首项、末项和中间项的 previous / next 计算正确且不循环。

### 构建与静态检查

1. `npm test` 通过新增队列测试。
2. 本功能涉及的 TypeScript 文件独立 `tsc --noEmit` 通过。
3. `npm run build` 成功并同步产物到 `web/dist`。
4. `go test ./...`、`go vet ./...` 通过，证明嵌入产物不影响 Go 项目。
5. `git diff --check` 通过。

### 手动验证

1. 名称升序下从图片依次切换到音频、视频和下一张图片。
2. 名称降序后，媒体切换顺序随列表一起反转。
3. 首项左按钮、末项右按钮禁用。
4. 点击按钮后继续按方向键，焦点保持时仍能切换。
5. 焦点位于视频 / 音频控件时，方向键不触发跨文件切换。
6. 图片、音频卡片和视频播放器中按钮位置与原有样式协调。
7. 亮色模式下检查按钮、focus ring 和禁用态；浏览器控制台无 warning / error。

## 上线与回滚

1. 不需要数据库迁移、配置开关、灰度协议或后端部署顺序。
2. 通过正常前端构建生成新的 hash 资源，并同步到 `web/dist` 后随 Go 二进制发布。
3. 回滚时同时还原前端源码和 `web/dist`；不存在需要清理的服务端数据。
4. 新旧前端都调用相同的 list/download API，可直接代码回滚。

## 建议实施顺序

1. 提取媒体识别、目录 / 搜索队列构建和邻项计算 helper。
2. 为 helper 增加顺序、过滤和边界单元测试。
3. 在 `PreviewModal` 接入派生队列和切换动作。
4. 增加两侧按钮、键盘和无障碍交互。
5. 更新快捷键文档并同步 `web/dist`。
6. 完成构建、Go 回归和浏览器手动验证。

## 风险与待确认问题

### 已处理风险

1. **排序不一致**：不在前端二次排序，只保留当前列表的相对顺序。
2. **音视频快捷键冲突**：焦点在原生播放器时不接管方向键。
3. **旧资源残留**：媒体元素以 `previewPath` 为 key 重新挂载。
4. **视觉偏离**：按用户要求复用现有图标、颜色、圆角和阴影，不做界面重设计。

### 待确认问题

当前没有阻塞实现或上线的待确认问题。触摸滑动、媒体预加载、可见计数器和跨分页切换均作为非阻塞后续能力，本期不实现。
